# AirNav-Agent 完成定义（Definition of Done）

> 建立时间：2026-09-28 ｜ 状态：**当前版本未完成，且原来的「完成」定义是错的**
> 相关：`docs/企业级差距清单.md`（分项验收标准）、`README.md`（能力现状）

---

## 一、为什么需要这份文档

`docs/企业级差距清单.md` 有 P0/P1/P2 每一**项**的验收标准，但它回答的是
「这一项做完了吗」，**没回答「整个项目什么时候可以停下来」**。

结果是开工一年也不会有「完成」那一刻 —— 因为「Agentic RL 主线」没有终点。

**这份文档的作用：把「完成」从一句感觉，变成三个可以逐条勾选、可以当场对质的层级。**

---

## 二、三层完成定义

三层的**目的不同**，验收方式也不同。混在一起谈就会变成「都重要 = 都没底」。

| 层级 | 目的 | 验收方式 | 状态 |
|---|---|---|---|
| **L1 工程完成** | 陌生机器上能装、能跑、能复现，且有证据 | 全部机械可验，见 §三 | ⬜ 7 项未做 |
| **L2 岗位完成** | 面试官能在 30 分钟内**看懂**并**复现** | 演示脚本 + 可访问远端 | ⬜ 未做 |
| **L3 产品完成** | 医生能拿去用 —— **本项目不做**，见 §五 | —— | ⛔ 明确放弃 |

## 三、L1 工程完成（7 条硬条件）

> 全部是机械可验的。「怎么验」一栏写的是**能当场跑出来的命令或能打开的文件**，
> 不是「应该没问题」。

### L1-4 一键启动

| 项 | 内容 |
|---|---|
| 判据 | 一条命令起 Web + 后端 + 探活推理后端，失败时**明确报哪一步坏了** |
| 怎么验 | 拔掉 gpu41 网络后执行 → 仍然能起，且界面/日志标注「降级模式」 |
| 现状 | ✅ **已完成（2026-09-30）**。判据下沉到 `agent/llm/client.probe_backend`（**只有一份**，CLI 与 Web 共用），另加 `degradation_note()` 出措辞。**CLI**：降级横幅 + `--json` 的 `backend_probe` 字段，不可达时 rc 仍为 0。**Web**：`/api/meta` 带 `backend_probe`（页面加载即显示横幅）、SSE 的 `degraded` 是**第一条事件**、审计 `params.degraded` 留痕。自检 `check_backend` 共 **7 层 24 项**（含反向用例），进第 15 项门禁 |

## 四、L2 岗位完成（这条才是真正要的）

> **判据不是「功能有」，而是「面试官能自己复现」。**
> 一个面试官不会 clone 你的仓库去跑 15 项门禁；他会看 3 分钟，然后决定要不要问。

| 项 | 判据 | 现状 |
|---|---|---|
| **L2-1 演示脚本** | 一份 5 分钟的现场演示流程：从提问 → 看 SSE 每步工具调用 → 拿到带三维视图的报告 → 当场改一个参数看结论变化。**写成一页纸，不用解释就能照做** | ✅ **已完成（2026-09-28）** → `docs/演示脚本.md`。四拍，每拍带实测耗时与「应该看到什么」；产物**当场生成**（实测删掉后 1 832 105 字节逐字节重建），所以干净 clone 也能全程跑完 |
| **L2-2 可访问的远端** | 面试官能给到 URL 或仓库地址，不需要内网、不需要 GPU | 🟡 **仍不满足**（2026-09-30 实测）。远端已建、CI 已绿（L1-1/L1-2 ✅），但仓库是**私有**的 —— GitHub 对私有仓库的未授权访问一律返回 **404 而非 403**（故意如此，避免泄露「仓库存在」）。实测三连：未登录 `HTTP 404` · 带 token 调 API `HTTP 200` · 对照公开仓库未登录 `HTTP 200`。**面试官没有凭据 → 打不开 → 在转 public 之前，这一项是「假达标」**。关键路径就是转 public（转前需再跑一次 `scan_creds --all` 与 PHI 守卫作为放行证据） |
| **L2-3 一页纸** | 「这是什么 / 为什么难 / 我怎么做的 / 证据在哪」四段，**证据全部是可点开的文件或命令** | ✅ **已完成（2026-09-28）** → `docs/一页纸.md`。所有数字标注来源（15 项门禁 / 344 条显式断言 / 650s / `agent/` 26 194 行 / 46 次提交（现算 2026-09-30）），没有一个是回忆的。⚠️ 09-30 复查发现原写「17 413 行入库 `.py`」**在任何口径下都复现不出来**（实为 `agent/` 去 `scripts/` 的 14 845 再叠加 `agent/render` 2 568 的重复计数），已改成带口径与命令的写法 |
| **L2-4 三条能讲的故事** | 每条都是「先看到假象 → 用物理判据推翻 → 修好 → 加一条会失败的哨兵」。**这是本项目的真正差异化** | ✅ **已完成（2026-09-28）** → 写进 `docs/一页纸.md §五`，每条都带证据行号与哨兵位置 |

L2-4 的三条候选（都在仓库里有完整证据）：

1. **`localhost:11434` 被 Remote-SSH 转发** → 看到 14b 就说明走的是转发（本机只有 7b）
   → 证据：`agent/llm/client.py` 注释、`docs/企业级差距清单.md`
2. **`.get()` 把「字段名写错」伪装成「这个数据没有」** → `stable_passed` 根本不存在，
   「加了重复读数」成了死代码而界面照常绿 → 证据：`agent/scripts/gate.py`、`PROJECT-NOTES §十三 13.17`
3. **评测分数是抽签** → 同一份代码三次跑出 93.3% / 83.3% / 91.1%；E13 的「调用 3 次」
   来自单份产物，四份并排实为 1 次(3)/4 次(1) → 证据：`docs/评测区分度_同义改写实验.md §8.9`

## 五、明确不做（砍掉这些，「完成」才会到来）

| 不做 | 理由 |
|---|---|
| ⛔ **临床级交付** | 需要器械注册、临床验证、责任主体 —— 不是个人能提供的，也不是简历要证明的 |
| ⛔ **多租户 SaaS / 公有云** | 目标是院内私有化部署，且与求职目标无关 |
| ⛔ **无外网一键部署（L1-7）** | 服务「交付给医院」这个不做的目标。**建议直接砍** |
| ⛔ **K8s / 微服务拆分 / LangChain** | 与 `企业级差距清单.md` §五 一致，收益为负 |
| ⚠️ **P2 病例库 / 多轮记忆 / 双人核对** | 都是「真实使用」层的功能，**除非面试反馈明确要，否则不做**。做了也证明不了 Agent 能力 |

**关键判断**：`企业级差距清单.md` 的 P1 五项里，只有 **CI / 打包 / 可观测** 服务于「能被复现」；
其余（队列、离线部署）服务的是「被运维」，而那是**产品**的事，不是**岗位**的事。

## 六、待用户决定的分叉（决定「完成」的形状）

| # | 决定 | 影响 |
|---|---|---|
| 1 | **远端仓库：私有还是公开？** | 公开 → L1-1/L1-2 可做，但必须先把硬编码 IP 清掉（L1-5）；私有 → L2-2 需要另做演示环境 |
| 2 | **容器里带不带 ollama？** | 带 → 镜像大、无 GPU 也能演示但慢；不带 → 镜像小、但演示依赖 gpu41 可达 |
| 3 | **演示走哪条主线？** | AirNav-Agent（Agent 工程）还是 Agentic RL（训练）—— 两个都在推进，**演示必须选一个当门面** |
| 4 | **L1-3/L1-4（打包 + 一键启动）做不做？** | 做 → 「能复现」的证据最硬，约 1~2 天；不做 → 靠 L2-1 演示脚本 + 录屏替代 |

## 七、推荐的最短路径（把 L1 收缩到服务 L2）

按「对求职的边际收益」排序，**只做这五件**：

| 序 | 事项 | 服务哪条 | 估计 |
|---|---|---|---|
| 1 | **清掉硬编码 IP**（实测 13 文件 / 22 处 → 环境变量） | L1-5，是所有对外动作的前置 | 半天 |
| 2 | **建远端 + CI 跑绿一次** | L1-1 / L1-2，让「证据在仓库里」成立 | 半天 |
| 3 | **写演示脚本 + 一页纸** | L2-1 / L2-3，面试官触点 | 一天 |
| 4 | **整理三条故事** | L2-4，差异化 | 半天 |
| 5 | **推理后端探活 + 降级标识** | L1-4，演示时不会因为 gpu41 抖动翻车 | 半天 |

**约 3 天。做完这五件，L2 就成立了 —— 项目的「求职使命」即告完成。**

L1-3（Docker）、L1-6（trace_id）、L1-7（离线部署）**排在 L2 之后**，
只有拿到面试反馈说「想自己跑一遍」时再做。

## 八、这份文档怎么用

- **每次决定「下一步做什么」之前**：先看 §五，确认这件事不在「不做」清单里
- **每次复核差距清单时**：同步更新 §三的「现状」一栏（它也会腐坏）
- **想说「快完成了」时**：逐条勾 §三的 7 条 —— 勾不满就是没完成，
  **别用「还剩几件事」来感觉进度**
