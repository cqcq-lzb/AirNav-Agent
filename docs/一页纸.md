# AirNav-Agent 一页纸

> 面向面试官。四段：**这是什么 / 为什么难 / 我怎么做的 / 证据在哪**。
> 每个数字都是命令现算的，不是回忆的；每条证据都是可点开的文件或可跑的命令。
> 生成日期 2026-09-28。

---

## 一、这是什么

把一套已有的**经支气管肺结节导航规划算法**（PySide6 + VTK 桌面程序，`D:\airway_navigation_v1`，只读）
重构成 **Agent 形态**：自然语言提问 → 手写 ReAct 循环 → 11 个领域工具 → 三维视图 + 合规报告。

一句话：**不是给算法套个聊天壳，而是把「规划结论从哪来」变成可追溯的**。

| 项 | 事实 |
|---|---|
| Agent 内核 | 手写 ReAct 循环（无 LangChain），11 个领域工具，pydantic 单一真相源 |
| 规划内核 | **与 V1 逐位一致**（`verify_planner` 硬门禁拦截） |
| 代码规模 | 17 413 行入库 `.py` / 38 次提交 |
| 验证强度 | **15 项回归门禁**，其中 **6 层显式断言共 344 条**（契约 28 · 网页 63 · 审计 35 · PHI 9 · 报告 66 · 临床 143）+ 3 组数值/评测门禁；实测约 11 分钟（650s），结论三态（通过·失败·不足以判定） |

## 二、为什么难（三条，每条都踩过）

1. **「能跑通」不等于「按你以为的那条路跑通」**。
   `localhost:11434` 看着通，其实是 Cursor 的 Remote-SSH 把它转发到了服务器 ——
   本机根本没在跑推理。**骗过我两次。**

2. **答对了字面、答错了题，评测看不出来**。
   模型自己传了 `max_diameter_mm=3`，旧代码把它**原样回显**成答案「至少 3.0mm」
   （真值 5.46mm），还附一句「调大参数重测」。而评测**照样判通过** ——
   因为它只断言「调过 `scan_device_fit`」+「数字可溯源」，
   而 `3.0` 恰好来自工具自己的返回体。**溯源判据在这里等于没判。**

3. **单次评测分数是抽签**。
   同一份代码，三种口径给出三个数：单次 **93.3%**、3 次全过 **83.3%**、
   尝试级 **91.1%**。三个都真，但**只有后两个说得清自己是什么口径**。

## 三、我怎么做的

### 3.1 结构上：让「错的来源」不可能出现

- **权威来源唯一**：`plan_route` 是结论权威，`rank_candidates` 只用于筛选 ——
  写进系统提示词**和**工具描述两处。
- **前置依赖**：工具带 `prerequisites()`，「没查病例就规划」在框架层被拒。
- **不让模型「推回给用户」**：器械外径不够时，工具**内部自动抬高上界继续收敛**，
  一次调用给真值 —— 而不是回显参数 + 让医生自己再试一次。
  （代价实测 +8~18s，换来答案从「回显」变成几何真值。）

### 3.2 验证上：每个结论都要能被推翻

| 手段 | 具体做法 |
|---|---|
| 判据钉**行为**不钉措辞 | 判别法：两条只差「有没有加一句说明」的回答，若一条过一条挂，就是尺子在卡措辞 |
| 主动制造故障 | 每个守卫都要**植入缺陷证明它会叫**（例：`check_backend` 7 层 24 项，三种植入缺陷分别被**不同断言**抓住 —— 去掉 meta 字段 19/20、`/health` 接上后端 23/24、降级事件挪到回答之后 23/24） |
| 结论三态 | `ok` / `bad` / `none`。**缺数据 ≠ 通过**；`int(d.get(k) or 0)` 是错的（缺键 ≠ 值为 0） |
| 夹具跟着仓库走 | 干净 clone 必须能跑；凑不出的边界值用**派生夹具**（按被测代码同一公式重算） |

### 3.3 工程上：让结果可被复现

- `python -m agent.scripts.gate` —— 15 项一键跑，含**几何对拍 · 规划数值 · 评测基线**三项硬门禁
- 后端不可达时**照常启动**并标注降级：CLI 打横幅 + `--json` 带 `backend_probe.degraded`；
  **网页端**在页面加载时显示降级横幅，且 SSE 的 `degraded` 是**第一条事件**
  （顺序就是信息 —— 排在回答之后，用户会把「连接失败」当结论读）。
  ⚠️ `/health` 刻意**不接**后端：它是存活探针，接上后端会让编排层误判「整个服务死了」
- 脱敏自检进代理门禁：凭据 · DLP 密文 · 硬编码内网地址

## 五、三条能讲的故事（本项目真正的差异化）

每条都是同一个形状：
**先看到一个假象 → 用一条「物理事实」判据推翻它 → 修好 → 加一条会失败的哨兵。**

### 故事 1｜`localhost:11434` 其实是服务器

- **假象**：本地 `ollama` 看着能用，`ollama ps` 显示 `100% GPU`，模型列表里还有 14b。
- **判据（物理事实）**：本机 `E:\ollama\models` 里**只装了 7b**（4.4 GB）。
  **看到 14b 就说明走的是转发。** 真凶是 Cursor / VS Code 的 Remote-SSH
  把 `localhost:11434` 转到了 gpu41。
- **修好**：`ollama` 预设默认模型改成本机实际安装的 7b；`doctor` 打印端口占用者，
  是转发就当场点破。
- **哨兵**：本机 `client.py` 里固化判据 + `doctor` 的端口探测。
- **证据**：`agent/llm/client.py:76-94`、`使用指南.md:116`

### 故事 2｜`.get()` 把「字段名写错」伪装成「这个数据没有」

- **假象**：我加了「同一用例跑 N 次的重复读数」，界面照常全绿，看着功能在工作。
- **物理事实**：我凭记忆读了 **不存在**的字段 `stable_passed`（真实字段是 `passed`）。
  于是 `if stable is not None` **恒假** —— 新代码是**死代码**，
  而**界面完全看不出来**。这比「没做」更坏：它让人以为做了。
- **修好**：改成读真实字段；并在 `gate.py` 里留下明确注释
  「**这里没有 `stable_passed` 这种字段，别再去找它**」。
- **哨兵**：凡「读外部报告字段」的代码，先打印 `list(data.keys())` 核对。
- **证据**：`agent/scripts/gate.py:384`、`PROJECT-NOTES.md §十三 13.17`

### 故事 3｜评测分数是抽签；「调用 3 次」是噪声

- **假象**：E13「调用链从 3 次降到 1 次」—— 看起来很漂亮的性能改进。
- **物理事实**：那个「3 次」只出现在**一份**产物里。四份 GPU 产物并排看，
  改前是 **1 次（3 份）/ 4 次（1 份）**，根本不是稳定 3 次。
  我**拿单份产物定了验收线** —— 量的是噪声。
  真正的病征是**答案被参数回显**（3.0 vs 真值 5.46）。
- **修好**：验收轴换成「**能否区分改前改后**」的轴（答案数值 3.0 → 5.46），
  E13 从 1/3 提到 **5/5**、E03 从 3/3 到 **5/5**。
  同时更正了成本claim：E03 14.37s → **32.41s（+126%）**，是净成本，不是「净收益为正」。
- **哨兵**：`run_eval --repeat N` 报**用例级**（N 次全过，卡基线）+ **尝试级**通过率，
  单列偶发；稳定失败 / 偶发 / 稳定通过必须被区分开（`eval/selftest` 第 5 组守着）。
- **证据**：`docs/评测区分度_同义改写实验.md §8.9`、`agent/eval/selftest.py`

---

**三条故事共同指向一件事**：这个项目最值钱的部分不是「功能多」，
而是**每个结论都知道自己是怎么被验证的，以及什么时候会失效**。
