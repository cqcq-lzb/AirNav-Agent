# 合成夹具病例（`fixtures/cases`）

> 一个几何合法、**不含任何患者信息**的小体积病例，让「依赖病例数据」的自检与门禁
> 在没有真实 `cases/` 的机器上也能真跑起来 —— 而不是整项跳过或静默空转。

生成脚本：`agent/scripts/make_fixture_case.py`
体积：**24.4 KB**（真实病例 LIDC_0089 是 75 MB，小约 3000 倍）
病例名：**沿用 `LIDC_0089`**（刻意如此，见下文「为什么沿用真病例名」）

---

## 一、为什么需要它

`cases/`（1.9 GB 真实 DICOM/NIfTI）因为**隐私 + 体积**不入库（见 `.gitignore`）。
直接后果是，在一台干净 clone 出来的机器上：

| 门禁项 | 干净 clone 上的状态（**做夹具之前**） |
|---|---|
| `planner` · 规划数值一致性 | **硬门禁**，却跑不了 |
| `loop` · ReAct 控制流 | 跑不了 |
| `payloads` · 工具返回体契约 | 跑不了 |
| `phi` · PHI 守卫 | 跑不了 |
| `eval` · 评测基线 | **硬门禁**，却跑不了 |

也就是说 —— 仓库里**最值钱的那批资产**（30 条用例、区分度实验、工具契约、
PHI 守卫）**恰恰最不可被外人验证**。这份夹具就是为了把这个洞补上。

对照：`.github/workflows/ci.yml` 里原本写着
> 想在 CI 上跑全量，必须提供脱敏 fixture 或自建 runner —— 属待办，不属已完成。

**本目录就是那条待办。**

---

## 二、它是什么

一个 `128 × 128 × 96`、spacing 全 1.0mm 的体积，含两张掩膜：

- **气道**：一串圆管拼成的主干 + 二级分叉，共 4 条可到达的末端分支
- **结节**：4 颗椭球，**按 z 递增**摆放（见「候选编号由什么决定」）

四张图（`ct.nii.gz` / `airway_mask.nii.gz` / `nodule_raw.nii.gz` / `entry_point.nii.gz`）
的 spacing / origin / direction **完全一致**，`stage4_manifest.json` 提供两套编号的映射。

### ⚠️ 每一条设计约束都来自源码里的断言，不是凭空造的

夹具不是「随便造个假数据」，它要**逐条满足**下游自检写死的期望：

| 夹具上的设计 | 来自哪条断言 | 实测值 |
|---|---|---|
| 恰好 **4** 颗结节 | `verify_payloads` 断言候选数为 4 | 4 ✅ |
| 候选 3 路过一段**真实收窄**（半径 2.2mm） | `device_too_thick` 分支要能被触发 | 最大外径 **3.51mm** |
| 候选在 1.5 / 2.0mm 器械下可过、6.0mm 下失败 | `scan_device_fit` 的上下界二分 | ✅ |
| 器械上限落在 **(2.0, 6.0)** 开区间内 | 二分搜索的收敛区间 | 3.51 ✅ |
| 4 个候选在 0.1mm 下**都有路** | 「按上限重试必须成功」 | ✅ |
| 候选 4 靶距落在 `marginal` 档 | `REACHABILITY_BANDS` 里只有 marginal 档含「人工复核」二字，E15 要这两个字 | **38.90mm** |
| 服务端编号**按体积降序**，与客户端顺序不同 | E02 考「两套编号的对应关系」，映射必须是**非恒等**的 | 1↔3, 2↔1, 3↔4, 4↔2 |

### 收窄段为什么必须真的有几何含义

候选 3 的路径中段放了一段半径 2.2mm 的细腰。**如果没有这段**，
`device_too_thick`、二分搜索、「按失败体给的 3.51mm 重试必须成功」全都没有几何含义
—— 那等于在测一个不会发生的分支。两侧的粗管还必须**离得够远**（18.5mm ≫ 4.5mm 半径），
否则管道的端帽会把细腰填实，收窄段就白做了。

### 候选编号由什么决定

`ndi.label` 按**扫描顺序**标连通域。所以结节球按 **z 递增**摆放，
才能让 `candidate_id` 与设计顺序一致。这是夹具能提供「非恒等映射」的前提。

## 三、来历必须可查（不许静默使用夹具）

夹具只在**真实病例缺席**时兜底，并且这件事必须能从工具输出本身看出来。
`agent/core/case_loader.py` 的三档来源：

1. `AIRNAV_CASES_DIR` 环境变量 —— 显式指定，**优先**（照 `AIRNAV_VIEWER_DIR` 的先例）
2. `<repo>/cases` —— 真实病例（不入库）
3. `<repo>/fixtures/cases` —— **合成夹具，兜底**

配套三个可查点：

- `cases_root_provenance()` → `{cases_root, kind: real|fixture|env, fixture, note}`
- `is_fixture(case_dir)` → 这个目录在不在夹具根下
- `CaseContext.summary()["fixture"]` → `true` 时，任何工具返回体里都会带上

```bash
# 显式用夹具跑（推荐，来历一目了然）
AIRNAV_CASES_DIR=D:/AirNav-Agent/fixtures/cases \
  D:/AirNav-Agent/.venv-mcp/Scripts/python.exe -m agent.scripts.gate
```

> **缺数据 ≠ 可以假装有数据。** 夹具兜底是可以的，静默兜底是不可以的。

## 四、重新生成

```bash
PY=D:/AirNav-Agent/.venv-mcp/Scripts/python.exe

# 生成（默认写到 <repo>/fixtures/cases）
"$PY" -m agent.scripts.make_fixture_case

# 生成并打印几何自检报告（上表那串数字）
"$PY" -m agent.scripts.make_fixture_case --report

# 写到别处
"$PY" -m agent.scripts.make_fixture_case --out D:/tmp/cases
```

夹具**随仓库入库**（`.gitignore` 里对 `fixtures/cases` 有显式放行 —— 注意
`cases/` 这条规则会匹配**任意层级**的 cases 目录，所以放行要写两步：
先放行目录本身，再放行其内容，否则子级例外不生效）。

## 五、它**不能**证明什么（别拿它当证据）

| 不能说 | 为什么 |
|---|---|
| 「规划数值与 V1 一致」 | 夹具**没有** `interactive_plans/`，没有可对拍的 V1 结果。`verify_planner` 在夹具上会明确返回 **退出码 2（不足以判定）**，门禁记 ⚪ |
| 「PHI 守卫有效」 | 夹具本来就不含 PHI。它能证明的是「守卫没把干净数据误报」，**不能**证明「有 PHI 时抓得住」——后者由 `phi` 项自己的 9 条自证覆盖 |
| 「评测分数是模型的真实水平」 | 夹具上的分数只说明**数据管线通**；真实评价要在真病例上跑 |
| 「几何在真实解剖上成立」 | 它是管道拼的，没有分叉角度的解剖合理性 |

这正是门禁里 `planner` 项显示 ⚪ 而**不是** ✅ 的原因：
**⚪ 与 ✅ 是两种东西，不许混。**

## 六、门禁上的表现

```bash
# 干净环境（无真实 cases/）：13 项 → 12 ✅ + 1 ⚪，无 ❌
AIRNAV_CASES_DIR=D:/AirNav-Agent/fixtures/cases "$PY" -m agent.scripts.gate --profile ci

# 真实病例：13 项 → 13 ✅
"$PY" -m agent.scripts.gate
```

`planner` 项的 ⚪ 是**预期状态**：退出码 2 只表示「这一项没跑成」，
不会让退出码变成 1 —— 否则干净副本上的 CI 会永远红着，那样门禁就没人看了。
但 ⚪ 也**不会**让门禁通过（`passed = not failed and not undecided and baseline_ok`），
所以它同样不能被当成「已通过」。
