## 一次规划实际跑了多少次搜索

「给这个结节规划一条路径」听起来是一次搜索，实际是**多对多**的批量搜索：

1. 先选出若干**靶点节点**：在中心线上取距结节掩膜最近的节点。
   去重间距 4mm（`TARGET_DEDUP_MM`），最多 6 个（`DEFAULT_MAX_TARGET_NODES`），
   并允许比最近距离多 12mm 的松弛（`DEFAULT_TARGET_DISTANCE_SLACK_MM`）。
   为什么要多个靶点？因为「离结节最近的骨架点」不一定就是最好走的那一个，
   相邻的一个点可能落在更宽的气道里。
2. 对每个靶点 × 每个代价配置（不指定时是 3 档）× 每一条可行边，
   跑一次多代价 A\*。
3. 收集全部可行方案（`proposals`），按分数排序，第一名作为交付路径。

所以「3 档对比」这一个动作背后可能是 18 次 A\*。这也是为什么工具层必须缓存
规划结果——不缓存的话，Agent 多问一句就要重算 20 秒。

## 评分公式

```
score = A* 搜索代价 + 2.0 × 靶点距离
```

排序键是 `(score, route_length_mm)` —— 分数相同时取路径更短的那条。

靶点距离乘 2.0 后计入总分，意味着「路走得好」和「终点离病灶近」要一起权衡。
若只按 A\* 代价排序，系统会偏好「走一条宽阔好走但离结节很远」的路径，
这在导航上毫无意义。

## 器械约束是硬剪枝，不是软惩罚

```
required_radius = 器械外径 / 2 + 安全余量
```

规划时对每条边取两端节点中**较小**的半径（`local_radius`），
只要 `local_radius < required_radius`，这条边直接返回 `None`——**从图上剪掉**。

这是硬约束而不是在代价里加惩罚项，差别很大：

- 硬剪枝 → 要么找不到路径（明确失败），要么找到的路径一定满足器械约束。
- 软惩罚 → 总能找到「一条路径」，但它可能物理上根本过不去，
  然后作为「成功」返回给上层。这正是要避免的失败模式。

后果：器械太粗时规划会**直接抛错**，而不是给一条勉强的路径。
错误信息里会带上器械外径、安全余量和被拦截的退化路径条数，
便于判断是「器械问题」还是「解剖问题」。

## 退化路径守卫

A\* 在某些情况下会返回「起点即终点」的单节点路径，其 `route_length_mm` 为 0，
但结构上是一个合法的返回值。V1 的 GUI 把它画成一个小点，没人会误读；
但 Agent 会把它当成「规划成功」。

因此加了守卫：`node_array.size < 2` 或 `route_length_mm < 1.0`
（`MIN_VALID_ROUTE_MM`）的方案被丢弃并计入 `degenerate` 计数。

这个守卫带来的副产品是：规划失败时能报出「已拦截 N 条退化路径」，
这比单纯说「找不到路径」信息量大得多——它说明图是连通的、搜索是跑了的，
只是没有一条够长的真实路径。

## 关键字段速查

| 字段 | 含义 |
|---|---|
| `route_length_mm` | 路径总长，沿中心线累加 |
| `minimum_diameter_mm` | 路径上最小气道直径（2 × 最小半径） |
| `minimum_clearance_mm` | 最小余量 = 最小半径 −（器械半径 + 安全余量）；未指定器械时为 `null` |
| `device_passable` | 是否满足器械约束；未指定器械时恒为 `true` |
| `maximum_turn_angle_deg` | 路径上最大转角，经平滑后计算 |
| `target_distance_mm` | 靶点节点到结节掩膜的最近距离 |
| `waypoint_count` | 路径航点数 |
| `reachability` | 可达性分级（见 KB-03） |
| `degenerate_routes_rejected` | 被守卫拦掉的退化方案数 |
| `bridge_voxels_on_route` | 路径经过的桥接体素数 |
| `recovered_voxels_on_route` | 路径经过的修复体素数 |

## 报告时不要只报一个数字

一条路径好不好，至少要看四个数：长度、最窄直径、最窄余量、最大转角。
只看长度会选出穿过细支的短路径，只看直径会选出绕远的长路径。
四个数一起给，取舍才可读。
