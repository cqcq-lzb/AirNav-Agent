## 从掩膜到可规划图，一共四步

1. **读掩膜**：`airway_mask`（nnU-Net 分割输出）与 CT，取 `spacing_zyx` 体素尺寸。
2. **骨架化**：`skimage.morphology.skeletonize(method="lee")`
   把三维气道压成一根体素级中心线。用 Lee 方法是因为它在三维下比经典细化
   更不容易在分叉处产生虚假的短枝。
3. **半径场**：对气道掩膜做 `distance_transform_edt`，
   每个骨架点取到最近非气道体素的距离，即该处**内切球半径**。
   乘上体素间距就得到以 mm 为单位的半径。这是后面所有「最窄直径」数字的来源。
4. **建图**：骨架点作为节点，八邻域连通作为边，边权是两点间欧氏距离（mm）。
   同时统计每个节点的**度**（邻居数）。

以 LIDC_0089 为例，产物规模：1938 个节点 / 1986 条边 / 176 个度 ≥ 3 的分叉点。
入口节点是 1936。

## 分叉点的判据

`degrees >= 3` 即判为分叉点。没有用角度阈值，也没有用半径突变，
就是单纯的度判据——简单、稳定、可复现。

判据简单带来一个后果：**不是所有「度 ≥ 3」的节点都是解剖学意义上的真正分叉**。
末梢的锯齿、分割表面的小凸起都可能造出度为 3 的节点。
所以 176 这个数字应当理解为「图上候选分叉点的个数」，
而不是「这段气道有 176 个真正的分叉」。报告里不要把两者混为一谈。

## 拓扑记号怎么读

路径经过的节点会被压成一个记号串，例如：

```
S163 > J78 > S107 > J53 > S110 > J55 > S114
```

- `S<n>` = segment，落在编号为 n 的**气道段**上（非分叉区域）
- `J<n>` = junction，落在编号为 n 的**分叉簇**上
- `N<n>` = 直接落到某个具体节点上（既不属于分叉簇也不属于段的兜底情况）

生成方式是先逐节点出原始记号，再把**连续重复的记号合并**。
所以 `S163 > J78 > S107` 读作：先走在 163 号段上，进入 78 号分叉，
再走上 107 号段。箭头方向就是从入口到靶点的行进方向。

## 记号串真正的用途

它的价值**不在数字本身，而在比较**：

- 两条路径的最窄直径、长度可能几乎一样，但拓扑记号完全不同。
  前者说明只是在同一根管子里做了微调，后者说明走了**不同的解剖分支**——
  这是两个量级不同的差异，必须在报告里分开说。
- 也可以用来做一致性检查：同一病例同一目标，换个代价配置后
  记号串如果变了，就说明配置真的影响了解剖走向，而不只是数值抖动。

## 气道修复段

分割结果常常在中段断开（层厚 2.5mm 造成的台阶、炎症导致的信号丢失）。
V1 会用额外的修复/桥接体素把断开处补上，否则中心线会中断、路径规划直接失败。

三个掩膜要分清：

- `airway_baseline_mask`：原始分割，未修复
- `airway_recovered_mask`：被修复找回的体素
- `airway_added_mask`：为连通而桥接的体素

规划结果里会统计**路径经过了多少修复体素与桥接体素**
（`bridge_voxels_on_route` / `recovered_voxels_on_route`）。

这个数字不是装饰。如果一条路径大量依赖桥接体素，说明它穿过的是
「算法认为连通、但原始分割里其实断开」的地方——真实镜下是否通得过，
需要人工确认。所以路径依赖修复段时必须给出注意事项。

## 中心线的一个容易踩的点

`centerline_points` 是**图的节点数组，不是有序折线**。
节点编号顺序与空间顺序无关——相邻编号的两个点可能相距 180mm 以上。

早期版本直接按数组顺序画中心线，结果画出一团横穿整个肺的乱麻。
正确的做法是从邻接表导出**边表**再画线段。
凡是消费中心线的代码都要注意这一点。
